# Errors & Root Causes 추출

## 어디서 캐나

- `qa-report.md`의 **FAIL 항목**
- `progress-log.md`의 "미처리 이슈", "결정" 섹션 중 에러 언급
- `harness-cost-log.txt`에서 `ERROR` 상태 레코드
- 커밋 메시지 `fix:` — **무슨 버그를 왜 고쳤는가**

## 각 에러 4단 구조

```markdown
- **증상 한 줄 요약**
  - 원인: 한두 문장 근본 원인
  - 해결: [파일:라인](../src/x.py#L42) 에서 `함수_이름()` 호출 — commit `abc1234`
  - 교훈: 재발 방지 포인트
```

## 각 칸이 답해야 할 질문

| 칸 | 질문 | 좋은 예 | 나쁜 예 |
|---|---|---|---|
| **증상** | "사용자가 나중에 검색할 짧고 특징적인 문구는?" | "watcher 가 빈 vault 경로에서 무한 retry 한다" | "에러 발생", "watcher 버그" |
| **원인** | "**근본** 원인은? (증상 복기가 아니라)" | "vault path가 None일 때 fallback 안 했고 retry timer가 재호출했음" | "watcher가 잘못 동작", "버그였음" |
| **해결** | "커밋 또는 코드 링크로 **증명**하라" | `[sync_engine.py:42](../src/x.py#L42) 에서 빈 경로 가드 추가 — commit abc1234` | "고침", "src/x.py 참조" |
| **교훈** | "다음에 이걸 피하려면 **뭘 봐야 하는가**?" | "fallback 경로 추가 시 retry 정책도 함께 점검" | "조심하기", "더 잘 하기" |

## 추출 원칙

- **fix: 커밋 메시지**가 핵심 단서. `git log --grep="^fix:"` 로 후보 수집
- 같은 증상이 여러 fix 커밋에 걸쳐 있으면 **하나의 항목**으로 통합. "처음 발견 → 부분 fix → 완전 fix" 흐름을 한 줄로
- "테스트 실패" 같은 *결과 묘사*보다 **무엇이 어떤 조건에서 깨졌는가** *조건 묘사*를 우선

## 일반화 원칙 (중요)

이 저널의 독자는 **다른 프로젝트 사람**일 수 있다. 그래서:

- 내부 함수명만 들고 가지 마라 → 함수 *역할*을 한 줄 풀어 쓰기
- 프로젝트 도메인 변수명은 **개념으로 일반화**
  - X "obsidian_vault_path 가 None"
  - O "노트 저장소 경로(obsidian_vault_path) 가 None"

## 커밋 참조 규칙

로컬 리포는 커밋 해시에 URL이 없어 **해시를 링크로 걸면 엉뚱한 파일로 이동**.

- X `커밋 [4b75e11](../src/x.py)` (해시 라벨이 파일 링크)
- O `[파일:라인](../src/x.py#L42) — commit \`4b75e11\``

파일 링크는 클릭 가능, 커밋 해시는 검색 가능한 백틱 코드. em dash `—` 로 구분.
