# Journal 톤과 링크 규칙

## 독자 가정 (최우선 원칙)

이 저널의 독자는 **이 프로젝트를 처음 보는 엔지니어** 또는 **다른 프로젝트에서 비슷한 문제를 마주한 사람**이다.

1. **프로젝트 내부 용어·함수명·약어를 날것 그대로 쓰지 마라.** 그대로 쓸 수밖에 없다면 **괄호로 뜻 병기** 또는 한 줄 풀어쓰기
   - ❌ `SprintTracer.span()이 누락됐다`
   - ✅ `스프린트 작업 구간을 기록하는 추적기(SprintTracer)의 span() 호출이 누락됐다`
   - ❌ `bypassPermissions 없이는 Bash가 막힌다`
   - ✅ `Claude Code의 권한 우회 모드(bypassPermissions) 없이는 셸 명령이 차단된다`
2. **이식 가능성 우선.** 이 프로젝트에서만 의미 있는 디테일은 일반화하거나 생략
3. **직관적 문장 구조** (전제·결과·이유 순). 에이전트 로그 그대로 옮기지 마라
4. 링크는 **원문 참조용 앵커**일 뿐. **본문만 읽어도 맥락 파악**돼야 한다

## 톤 규칙

- 한국어 섹션 제목 + 한국어 내용
- 함수명/커밋/파일명은 원문 유지 (영어). 단, **처음 등장하는 프로젝트 고유 심볼은 괄호로 역할 풀어쓰기**
  - 예: `SyncEngine(로컬↔원격 파일 상태를 맞추는 동기화 엔진)`
- 약어·두문자어는 **첫 등장 시 풀어쓰기**
  - 예: `QA(Quality Assurance, 품질 검증)`, `TDD(테스트 주도 개발)`
- "우리는", "저는" 같은 1인칭 금지. 사실 기술
- 추측은 `(추정)` 꼬리표
- **다른 프로젝트 독자를 항상 의식하라.** 한 문장 쓸 때마다 "이 문장이 이 프로젝트 모르는 사람에게도 의미 있는가?" 자문

## 링크 규칙 (엄수)

- **모든 파일/코드 참조는 마크다운 링크**. `src/x.py` 같은 평문 금지
- 형식: `[라벨](상대경로#Lline)` 또는 `[라벨](상대경로)`
- 라벨 예시:
  - 함수/메서드: `apply_changes()`, `SprintTracer.span()`
  - 파일: `sync_engine.py`, `decision-003.md`
  - 커밋: `commit abc1234` (SHA 첫 7자)
- 상대 경로는 `docs/journal.md` 기준. `../artifacts/...`, `../src/...`
- 라인 앵커 `#L42` 는 해당 라인이 실제 존재할 때만. 파일 전체 참조는 앵커 없이

## 커밋 참조 (중요)

로컬 리포는 커밋 해시에 URL이 없어 **해시를 링크로 걸면 엉뚱한 파일로 이동**.

- ❌ 금지: `커밋 [4b75e11](../src/x.py)`
- ✅ 권장: `[파일:라인](../src/x.py#L42) — commit \`4b75e11\``

파일 링크는 클릭 가능, 커밋 해시는 검색 가능한 백틱 코드. 한 줄에 병기할 때 em dash `—` 로 구분.

## 한 줄 요약 예시

```
Obsidian(마크다운 노트 앱) ↔ Google Drive 양방향 동기화의 1차 구현을 Sprint 1~4로 완료 (총 269 tests / 커버리지 93%). 동기화 엔진을 네 축 — 로컬 상태 추적(state), Drive API 어댑터(drive), 충돌 해소(reconcile), 파일 생명주기(lifecycle) — 으로 분리해 완성. 이월 건: 파일 변경 감시기(watcher)의 예외 모니터링 공백.
```

이 한 줄만 읽고 외부 독자가 "이 프로젝트가 뭘 했는지" 파악할 수 있어야 한다.
