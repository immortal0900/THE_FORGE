# Decisions & Tips 추출

## Decisions 섹션

### 어디서 캐나
- `decisions/decision-*.md` 본문 요약
- `progress-log.md`의 "결정" 섹션
- 중요한 `refactor:` 커밋의 동기

### 형식

```markdown
- **결정 제목** (근거: [decision-003.md](../artifacts/decisions/decision-003.md))
  - 고려안: A / B / C
  - 선택: C — 이유 한 줄
  - 영향: [변경된 파일](../src/y.py#L10)
```

### 답해야 할 질문

- **고려안**: "어떤 선택지가 테이블에 있었나?" — 3개 이하면 모두, 많으면 핵심만
- **선택**: "어느 걸 골랐고 **왜**? (1줄)" — axiom 부합 / 비용 / 사용자 영향 중 하나로
- **영향**: "이 결정이 코드 어디에 박혔나?" — 가장 대표적인 파일:라인

### 사소한 결정은 빼라

변수명, 라이브러리 함수 호출 형태, 들여쓰기 같은 결정은 저널 자산이 아니다. **다른 프로젝트에서도 참고 가치 있는** 결정만 추출.

## Tips & Gotchas 섹션

### 추출 대상

- **하네스/도구 설정의 미묘한 함정**
  - 예: "Claude Code의 권한 우회 모드(`bypassPermissions`) 없이는 셸 실행이 차단된다"
- **재사용 가능한 패턴** (도구·프레임워크 고유명은 최초 등장 시 한 줄 설명 병기)
- **프로젝트 고유 비즈니스 로직 팁은 제외** — 범용 재사용 가능한 것만

### 형식

```markdown
- **함정 한 줄 (일반화해서 기술)** — [관련 코드](../src/z.py#L10) 참고
- **효과적이었던 패턴** — 도구/개념 이름을 풀어서 기술
```

### 좋은 예 / 나쁜 예

| | 좋은 예 | 나쁜 예 |
|---|---|---|
| 일반화 | "파일 diff 적용 시 라인 단위가 아닌 블록 단위로 patch 하는 방식이 빠르다 (내부 함수 `X.apply()`)" | "`X.apply()` 가 빠르다" |
| 풀어쓰기 | "스프린트 작업 구간을 기록하는 추적기(SprintTracer)의 span() 호출이 누락됐다" | "SprintTracer.span() 누락" |
| 함정 | "Claude Code의 권한 우회 모드(`bypassPermissions`) 없이는 셸 실행이 차단된다" | "bypassPermissions 없이는 Bash 막힘" |

## 핵심 원칙

내부 함수/클래스 이름을 **중심**으로 서술하지 마라. **문제와 해법을 먼저** 서술하고, 내부 심볼은 **괄호·링크로 보조**.

다른 프로젝트에서 이 저널을 읽는 사람이 "이 팁이 우리 프로젝트에도 적용되나?" 한 줄로 판단할 수 있어야 한다.
